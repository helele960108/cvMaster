## 原则

界面沿用已确认的菜单栏浮层，不扩展管理窗口。优先系统控件、语义颜色、SF Symbols、原生 transient popover、系统菜单和确认提示。视觉装饰不应增加常驻原图、复杂动画或额外窗口。

当前目标为 Apple Silicon / macOS 26.5，使用 Swift 6；遵循平台交互方向不等于已经通过 Apple 审核或所有辅助功能验证。

## 模块职责

- `ClipboardMonitor`：500 ms 变化检测、明确启用、持久化暂停、休眠 / 会话状态、安全输入、来源排除、敏感标记和受控格式采集。AppKit 剪贴板读取仍在 MainActor。
- `ClipboardCapturePolicy` / `ClipboardChangeCursor`：可用合成数据验证的多表示选择策略与两阶段变化游标，不访问系统剪贴板。
- `ClipboardLibrary`：MainActor 上的有界 UI 投影、防抖 / 版本防串序、用例编排、按需预览。清空前等待已接收写入结束，防止旧快照在清空后重新入库。
- `HistoryStore`：actor 串行 SQLite、内容指纹、关系分组、事务化容量 / 保留清理、私有资产读写及恢复。actor 隔离不等于独占一条 OS 线程。
- `ThumbnailPipeline`：专属 GCD 队列上的有界文件读取与 ImageIO 解码；不占用存储 actor 或 Swift 协作线程池执行阻塞工作。
- `PasteTargetWorker`：串行后台 AX 身份捕获、原输入节点焦点恢复与校验。AX 引用只由该队列访问，MainActor 只接收 UUID / PID 等不可变元数据，不读取目标输入内容。
- `PasteHandoffPolicy`：纯状态的单次粘贴请求绑定、关闭失效和预期激活确认，避免读取期间用户切换应用后仍恢复旧目标，或正常恢复事件延迟投递而误使结果失效。
- `PasteFocusRestorationRequest`：单次请求的线程安全撤销许可；原应用恢复确认后才创建，切换应用、关闭、超时、取消或结束后不得继续发起焦点写入，每请求最多一次恢复。
- `QuickPanelView`：原生轻量列表，不读文件、不查询数据库、不保留完整历史内容。
- 辅助功能状态在打开浮层、应用激活和进入设置时刷新，粘贴关键边界重新检查真实授权。
- 登录项由系统 `SMAppService` 管理，不生成 LaunchAgent；全局快捷键使用 Carbon 注册，设置页只做本地按键捕获，不安装全局输入监听。

## 明确预算

| 对象 | 约束 |
| --- | --- |
| 首屏元数据 | 60 条 |
| 当前最大加载 | 300 条，关闭浮层缩回首屏 |
| 待入库大内容 | 单次一个任务，无积压队列 |
| 单表示 / 单条 | 8 MiB / 16 MiB |
| 一次表示数量 | 24 个 |
| 可搜索文本 | 每条最多 32,768 字符 |
| 详情文本 | 16,000 字节正文前缀，额外保留截断说明空间 |
| RTF 解析 | 每条摘要 / 详情 / 纯文本转换分别共享 256 KiB 输入预算 |
| 缩略图 | 列表最长边 640 px，详情 420 px；单张编码至多 2 MiB |
| 正向缩略图缓存 | stored 图的两个尺寸共享 24 张 / 2 MiB；引用原文件不长期缓存 |
| 缩略图阻塞工作 | 最多 2 个实际未结束任务，零待执行工作队列；调用方最多 12 个当前请求 |
| 缩略图合并 / 冷却 | 同源同尺寸合并；每个工作最多 128 个等待者，失败冷却表最多 256 项 |
| SQLite 页缓存 | 约 2 MiB，不含 OS 缓存 |
| 历史上限 | 总计 10,000 条 / 1 GB 原始表示，包含保护记录 |

以上不是进程常驻内存承诺。系统框架、延迟 pasteboard 提供者、SQLite、解码临时内存和 OS 文件缓存仍需实测。外部图片最多 64 MiB，两个缩略图工作最坏可同时持有 128 MiB 原始压缩输入，另有解码及编码缓冲。

1 GB 不包含 SQLite 元数据、trigram 索引、WAL、临时文件或引用文件本体；目前没有整体硬磁盘配额。trigram 的完整位置索引可能明显增加磁盘用量，不能将此预算解释成整个目录至多 1 GB。

## 搜索与容量查询

搜索有 140 ms 防抖。3 个及以上 Unicode 码点在 SQLite 支持 FTS5 trigram 时先用转义后的完整短语 MATCH 取候选，再使用原有转义 LIKE 复核，保留中文子串、ASCII 大小写以及 `%` / `_` / `\\` 等字面匹配语义；1–2 码点及不适用索引的查询继续 LIKE。所有用户参数绑定，不拼接进 SQL。图片仍不参与非空关键词搜索。

索引采用 external-content，不重复保存完整搜索正文；位置 postings 仍有空间成本。能力不可用或可选索引初始化失败时回退 LIKE。dirty 标记及触发器确保能力恢复后重建索引，不让缺失的 tokenizer 阻断历史库正常写入。

保留独立的匹配计数，不盲目以 `COUNT OVER` 强制全体窗口计算 / 排序。当前页分组关联一次批量读取，避免每行一个查询。容量 COUNT / SUM 合并并缓存，只在内容变更后重算，搜索不重复扫描全库容量。

查询入口、主要语句间及行间检查取消；正在运行的 `sqlite3_step` 不承诺被中断。查询版本继续拒绝旧结果。加载更多仍采用递增 LIMIT 重查最多 300 条，并非 keyset 分页；在固定 UI 上限下保留此简单行为。

## 采集、复制与隐私边界

首次默认关闭记录；开启、暂停、恢复、休眠 / 会话变化、安全输入阻断和自身写入均更新采集基线，不回补被阻断期间最后一条内容。暂停状态保存在 UserDefaults，重启不自动恢复记录。

变化检测采用两阶段 `ClipboardChangeCursor`：观察新 changeCount 仅创建 pending，结果确定后才提交。item / 类型尚未声明或必要表示返回 nil 时保留同代数 pending，复用 500 ms 轮询，在首次尝试起 1.5 秒内最多重试 3 次；超时 / 耗尽只报告一次。确定的空 Data、无效文件 URL、预算超限及不支持类型不作为未就绪无限重读。可用同 item 格式仍可回退，缺失可选格式不阻挡完整必要表示。pending 不保留 Data，最多保留一个代数与首次观察到的来源；新代数替代旧 pending，过期请求身份不能提交重置后的同计数请求。计数使用不等比较，不假定只增不减。

读取期间 changeCount 改变不再重置为最新基线；下一轮尝试新代数。生命周期 / 记录开关 / 隐私上下文失效仍清空 pending 并推进基线；已重置或停止的旧读取只丢弃结果，不再次推进基线。观察到任何不同计数（含回到 committedChange）均使旧 pending 失效；敏感标记只终结当前请求。来源推断在同代数重试期间保持首次观察值，重试、逐个表示读取前后及最终交付均重新核对首次来源和当前前台应用的排除配置。后台存储忙时仍终结本次变化并计数，不新增无界快照队列。

公开的会话 on-console / login-complete 状态、安全输入标记和工作区通知按不安全状态保守阻断，缺失会话状态也阻断。但会话失活通知不等于锁屏通知，这些公开信号无法证明覆盖所有锁屏或密码场景，不能承诺“锁屏绝不采集”或“所有密码都被过滤”。来源应用是推断值，排除列表也不是安全边界。

格式选择先为每个受支持 item 预留必要表示，再补充可选格式；文件 item 必须有有效文件 URL，不能以像素替代。可选超大 HTML / 图片可跳过，但不会静默遗漏整个受支持 item 后恢复不完整多文件。延迟读取前后重新验证状态、敏感标记和 changeCount，避免混合不同剪贴板版本。

AppKit 延迟提供者在读取前无法可靠获知数据大小，系统调用仍可能阻塞 MainActor；读取后检查 8 / 16 MiB 限额不是该调用的硬内存 / 时间上界。未擅自把未明确支持后台线程的 AppKit 流程移到工作队列。

自动粘贴采用“粘贴至当前激活的 APP”语义：打开列表时固定外部前台 APP；列表自身成为前台时不把 cvMaster 当作目标，也不追踪并收养第三个 APP。先准备全部有界表示与临时 item，再关闭列表、必要时激活绑定 APP；目标连续 100 ms 为前台且 active、cvMaster 已失活、修饰键释放后确认准备完成，不要求已激活 APP 产生重复激活通知。准备期间应用激活代数变化重新计时；第三方激活、非预期关闭、取消、权限缺失或超时撤销请求。

自动粘贴主链路不再读取 AX 窗口 / 输入节点，不要求原节点可编辑或可写，也不设置 AXFocused。写入前后均检查同一请求、激活代数、前台 PID、active 状态和截止时间，然后无 await 地向目标 PID 发送 ⌘V，由目标 APP 当前 responder 处理。仍需辅助功能权限；不使用全局 HID 路由、不模拟坐标点击或自动提交消息。不保证目标一定保留输入焦点、支持当前格式或实际接收粘贴；“事件已发送”不等于“内容已插入”。旧 PasteTargetWorker / PasteFocusRestoration 实现保留但不再接入生产自动粘贴路径。

系统剪贴板写入失败仍可能改变剪贴板，不能宣称自动恢复旧值。授权在写入后撤销时提示目标不可用 / 可手动粘贴，不错误声称“剪贴板未改变”。失败反馈仅在原进程或本应用仍在前台时自动显示，避免迟到错误抢走用户刚切换的应用焦点。

RTF 原始内容仍可正常保存与恢复；纯文本转换只限制实际参与解析的 RTF，总预算超限明确失败，不返回截断文本；纯 UTF-8 内容不受 256 KiB RTF 解析预算限制。不使用 HTML 渲染器加载外部资源。

## 存储一致性与访问权限

根目录、assets 为当前用户所有的 0700 目录；数据库在 SQLite 打开之前以 0600 创建，已有 DB / WAL / SHM / journal 先检查普通文件、单硬链接、所有者及 no-follow，再收紧为 0600。SQLite 使用 `SQLITE_OPEN_NOFOLLOW`。原始资产使用目录描述符相对 open / unlink、UUID 独占创建和 0600 起始权限，读取拒绝符号链接、非普通文件及不一致大小。

应用目录和已知子目录拒绝符号链接；这不是对同 UID 恶意进程可任意修改所有祖先目录 / SQLite VFS 文件的完全隔离。权限限制不防御同用户进程或备份访问，未引入应用级加密，也未更改现有 bundle ID、用户授权、登录项身份。

自动保留 / 容量清理和新增或去重更新共享一个 SQLite 事务；新资产写入失败时回滚旧元数据并移除本次新文件。旧资产只在提交成功后 unlink，崩溃遗留的 UUID 孤立文件下次启动回收。SQLite 每个读取循环都检查错误，避免把不完整引用扫描当作完整结果并误删文件。

手动清理的成功边界是 DELETE 提交。孤立资产清理、checkpoint 是 best-effort，失败记录无内容日志，不把已提交删除伪装成回滚。取消清理路径中的全量 VACUUM，释放页保留供复用，数据库文件不保证立即缩小。删除也不等于从 SSD、WAL 残留、系统快照或备份安全擦除。

## 缩略图和外部文件

真实文件读取 / ImageIO 解码最多两个工作。超时或取消使等待者及时返回，但工作许可保留到同步调用真正结束，不能靠超时不断新增卡死线程。只对 busy 做最多三次调用方尝试（80 / 160 ms 取消感知退避），真实失败 / 超时进入有界冷却；没有无限重试队列。

所有资产和外部图像均先以 no-follow 描述符读取有界 Data，再交给 ImageIO，不按检查过的 URL 再次打开；外部引用继续要求本地普通图片、非未下载云占位文件。元数据预检和打开仍不是对同 UID 修改路径的原子安全事务，`O_NONBLOCK` 也不能让普通文件 syscall 保证及时返回。

复制文件引用的可读性检查同样在 actor 外的有界工作中执行，最多两个实际未结束检查，3 秒等待期限；失败 / 满载拒绝恢复。返回 actor 后检查取消及内容代数，删除 / 清空后的旧载荷不会继续交付。文件检查不等于复制时永久有效的访问凭证，原文件仍可在检查后移动或撤权。

列表 640 px 与详情 420 px 分开作为缓存键，共享缓存预算，不在存储 actor 内新增 ImageIO 降采样，也不在 pipeline 隐藏第二份正向缓存。同源同尺寸请求合并，不跨尺寸合并原图解码。删除 / 清空 / 自动清理令在途结果失效，不能把已删除资产的结果重新装入缓存。

## 验证边界

允许 `native/scripts/check-regressions.sh` 编译独立命令行验证器，只使用带所有权标记的临时目录和合成内容，不实例化真实采集器、不启动应用、不读写 `NSPasteboard.general` 或真实应用数据库，不创建 XCTest 测试类。Swift 6 严格类型检查、脚本语法、plist 和构建也不等于真实交互通过。

仍需人工 / Instruments 验收：跨来源应用的多格式恢复、系统安全输入与会话切换、原生 AX 兼容性 / 焦点交接、多屏 / 全屏 / 菜单栏自动隐藏、VoiceOver、最低硬件冷 / 热唤起、空闲 CPU、峰值内存及长时间运行。隔离回归和基准的实际结果另见本轮验证记录，不能把未执行项目写成已通过。

粘贴交接在请求绑定及主动关闭浮层后，使用 macOS 14+ 的 `NSApp.yieldActivation(to:)` 向保存的目标进程让出激活权，再 deactivate / activate；activate 返回成功仅表示请求接受，仍需检查实际 active / frontmost 状态并稳定等待；工作区激活事件用于撤销第三方切换及更新代数，不再把重复通知当作必要条件。
