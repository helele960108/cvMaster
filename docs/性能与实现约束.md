# 本地实现与性能约束

> author：helele
>
> since：2026-10-19

## 原则

界面沿用已确认的菜单栏浮层，不扩展管理窗口。优先系统控件、语义颜色、SF Symbols、原生 transient popover、系统菜单和确认提示。视觉装饰不应增加常驻原图、复杂动画或额外窗口。

当前使用 macOS 26.5 SDK 的原生 API；遵循平台交互方向不等于已经通过 Apple 审核或所有辅助功能验证。

## 模块职责

- `ClipboardMonitor`：500 ms 变化检测、明确启用、暂停、休眠、来源排除、敏感标记和受控格式采集。
- `ClipboardLibrary`：主线程 UI 投影、防抖 / 版本防串序、用例编排、按需预览、复制成功回收浮层。
- `HistoryStore`：专用 actor 串行 SQLite、资产原子写入、稳定指纹、关系分组、容量 / 保留清理及恢复。
- `QuickPanelView`：原生轻量列表，不读文件、不查询数据库、不保留完整历史内容。

## 明确预算

| 对象 | 约束 |
| --- | --- |
| 首屏元数据 | 60 条 |
| 当前最大加载 | 300 条，关闭浮层缩回首屏 |
| 待入库大内容 | 单次一个任务，无积压队列 |
| 单表示 / 单条 | 8 MB / 16 MB |
| 一次表示数量 | 24 个 |
| 可搜索文本 | 每条最多 32,768 字符 |
| 详情 | 16 KB 文本前缀、420 px 单缩略图 |
| SQLite 页缓存 | 约 2 MB，不含 OS 缓存 |
| 历史上限 | 10,000 条 / 1 GB 原始表示，保护条目不被自动删 |

内存预算不是进程常驻内存承诺；系统框架、pasteboard 提供者、SQLite、解码临时内存和文件缓存仍需实际测量。1 GB 不包含元数据及 WAL，硬磁盘配额后续补充。

## 速度与一致性

搜索由后台 SQLite 执行，140 ms 防抖，输入参数绑定，查询版本防止过期结果覆盖新条件。当前使用 LIKE 以覆盖中文子串，不宣称 FTS 性能；10,000 条最长文本情形须测量，后续可按数据引入适配中文的索引。

原始文件只在复制时读取；准备成功后才清空剪贴板，自写 changeCount 被抑制。系统写入失败仍可能改变剪贴板，因此必须提示，不能宣称事务恢复旧剪贴板。分组、置顶与删除失败均反馈，不静默伪造成功。

内容文件先写后发布元数据，失败回收新文件；启动扫描应用资产清理孤立文件。删除只触及 UUID 命名的应用资产，不删除用户原文件。清空期间拒绝新采集快照；actor 串行顺序保证先前提交完成后再清空。

## 后续运行验收（尚未执行）

1. 首次启用前零采集，启用 / 暂停 / 恢复不追溯已有剪贴板。
2. 纯文本、URL、多文件、图片与 RTF / HTML 表示跨应用恢复。
3. 重启持久化、去重保留分组、删除 / 清空不触及原文件。
4. 高频连续复制的跳过行为与内存上界；超大及延迟提供数据不卡死流程。
5. 输入快速变化、切换分组 / 类型、展开关闭预览，无旧结果串入。
6. 静态内存、峰值、睡眠唤醒、低电量、冷 / 热唤起、搜索 P50 / P95 的 Instruments 记录。
7. 浅深色、高对比度、减少动态、VoiceOver、键盘流程、点击外部关闭、多屏与全屏。
8. 磁盘满、损坏库、文件不可读、退出中断写入、快捷键冲突。

本轮遵循仅静态检查，不自动启动新版读写真实剪贴板，不新增单元测试类，不执行 Maven；不把未做的运行验收写为通过。
