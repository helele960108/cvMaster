## macOS 独立锁屏检测（2026-11-04）

- **状态来源**：`SessionLockMonitor` 读取 `CGSessionCopyCurrentDictionary()` 的 `CGSSessionScreenIsLocked` 键，并监听 `com.apple.screenIsLocked` / `com.apple.screenIsUnlocked` 分布式通知。字典明确为真时锁定，键缺失或明确为假时未锁定；字典缺失或值类型异常时 fail-closed 为锁定；锁屏通知先于字典更新时保留 750 ms 保护窗口。
- **采集门禁**：`ClipboardCapturePolicy.isBlocked` 增加 `screenLocked`，轮询、读取前后和最终交付均复核。锁屏 / 解锁转换重置采集基线，不补采锁屏期间内容；轮询间隔超过 5 秒时也保守重置基线，覆盖 App Nap / 系统暂停期间错过的锁屏通知。
- **在途快照**：锁屏转换调用 `ClipboardLibrary.invalidatePendingCapture()`，递增隐私代数并取消尚未开始保存的任务；保存任务在写库前复核代数和实时门禁。已进入 SQLite 事务的保存无法回滚，但完成后不再刷新列表；在途任务结束前保持 `captureBusy`，避免旧保存与新采集交叉。
- **已执行验证**：`check-regressions.sh` 新增纯解析器 / 门禁 / 轮询间隔回归，**19 组**合成回归全部通过；`build-app.sh` 优化构建通过；`check-ax.sh` 的真实跨进程 AX 回归（恢复原输入节点、拒绝切换到其他输入框）通过。另以只读方式检查当前未锁屏会话字典：`CGSSessionScreenIsLocked` 缺失，`kCGSSessionOnConsoleKey` / `kCGSessionLoginDoneKey` 均为 1，与“键缺失按未锁定”的解析分支一致；未触发真实锁屏。
- **未执行验证**：没有自动触发真实锁屏，避免影响当前桌面会话；锁屏 / 解锁、通知丢失、App Nap / 睡眠期间的实际轮询停顿、快速用户切换、FileVault 登录窗口及锁屏期间复制仍需人工桌面验收。合成回归只证明纯解析和策略，不证明系统通知一定送达。

### 验证过程中修正的问题

- 实际编译发现 actor 的普通 `deinit` 不能访问 non-Sendable SQLite 指针；改为当前 Swift 6.4 支持的 `isolated deinit`，未以 unsafe Sendable 指针绕过隔离。
- 首次整体验证遇到源文件同时更新，稳定副本重跑后通过，不将该次中断算作通过。
- 首轮隔离迁移夹具在 SQLite 打开阶段失败，而非迁移 SQL 失败。Foundation 的 URL 标准化将 `/private/tmp` 重写为 `/tmp` 符号链接别名，触发 `SQLITE_OPEN_NOFOLLOW` 拒绝。runner 使用 `pwd -P` 生成物理临时路径，验证器不再重新标准化；未削弱生产 no-follow 检查。注入目录同样应使用没有祖先别名的物理路径。

## 搜索基准

环境：Apple M4，10 核，16 GiB 内存，macOS 26.6.2（25G83），Swift 6.4，SDK 27.0、deployment target macOS 26.5，系统 SQLite 3.51.0。

方法：每个文本长度使用同一个逐步填充的临时数据库，分别达到 1,000 / 5,000 / 10,000 条。内容为重复的 ASCII / 中文及标点混合文本，约每 97 条加入选择性关键词；事务批量构造后 checkpoint。每个查询预热一次，再测 15 次，P95 按 nearest-rank 取第 15 个样本（即本组最大值）。

“生产 page”包含真实 actor 调用、分页投影、分组关联及统计路径；“LIKE 基线”仅执行匹配计数和 ID 查询，工作更少。因此数据用于观察索引选择的收益 / 退化，不能解释为严格同工作量的前后版本比较，也不是 UI 延迟、冷盘性能或 Instruments 内存结果。重复合成文本不代表最坏 trigram postings 分布。

## 菜单栏打开后的原输入焦点恢复修复

本轮针对“先聚焦微信输入框，再点击菜单栏图标，选择条目后无法粘贴”的交接路径补齐恢复逻辑，不改变浮层 UI 或选择 / 粘贴操作规则：

- 菜单栏改为鼠标按下触发，并在回调返回前完成后台 AX 捕获工作的入队。捕获句柄支持后台结果先于等待者完成，不在主线程执行或等待 AX。
- 原应用激活确认后，使用共享 700 ms 预算准备输入焦点。原窗口及原节点身份、可编辑性和公开焦点属性的可写性均通过检查后，每请求最多对原节点设置一次 `AXFocused`；之后只观察稳定状态和深度校验，不反复恢复、不补抓新输入框。
- 当前焦点指向另一个输入框、原窗口变化、AX 错误、取消、超时或目标身份不符时拒绝。应用激活 / 浮层关闭事件同步撤销恢复许可，旧请求不能因切回原应用而复活。写入剪贴板后仍只校验，不恢复焦点。
- 写后最终异步校验和按键派发均受原准备结果的截止时间约束，不因另开校验预算延长授权。
