## 1. 项目目标

开发一款原生 macOS 剪贴板管理工具，在不打扰用户日常操作的前提下，自动记录可支持的剪贴板内容，并提供快速检索、分组整理、置顶和再次使用能力。

核心方向：

- **原生体验**：采用 Apple 平台原生技术，交互、快捷键、窗口行为与系统风格一致。
- **高性能**：常驻后台低开销，大体积图片和文件处理不阻塞交互，历史增长后仍可快速检索。
- **美观易用**：简洁、精致，支持浅色与深色模式，兼顾键盘操作和鼠标操作。
- **结构化管理**：支持历史列表、用户分组、置顶及清晰的保留策略。
- **多类型内容**：覆盖文本、链接、图片、文件引用及应用提供的常见富文本表示。
- **面向扩展**：一期本地优先；后续可增加跨设备自动同步及 Apple 移动端。
- **隐私可控**：剪贴板可能包含密码、令牌和个人资料，隐私保护是基础要求。

## 2. 平台与设计假设

| 项目 | 初始建议 | 说明 |
| --- | --- | --- |
| 一期平台 | macOS | 暂不开发 iPhone / iPad 客户端 |
| 处理器架构 | Apple Silicon（arm64） | 暂将“只支持 Apple 系列”理解为不支持 Intel Mac，需确认 |
| 最低系统版本 | 建议 macOS 14.0 | 正式立项时结合系统 API、发行渠道和目标用户覆盖率确认 |
| 开发语言 | Swift | 原生 UI 使用 SwiftUI，必要的系统交互使用 AppKit |
| 产品形态 | 菜单栏常驻图标 + 图标下方的唯一列表浮层 | 不显示 Dock 图标，不创建常规管理主窗口 |
| 存储原则 | 本地优先，离线可用 | 一期不依赖账号、网络服务或云端 |
| 数据建模 | 关系型元数据 + 独立内容文件 | 禁止使用 JSON 字段存储业务数据 |

本文中的指标为设计目标，不代表已经完成实测；存在不确定性的系统行为须通过技术验证后确定。

## 3. 范围划分

### 3.1 一期必须具备

1. 剪贴板自动监听、内容识别、持久化与重复内容合并。
2. 文本、链接、图片、文件引用及常见富文本内容的识别与展示。
3. 历史记录列表、内容预览、文本搜索与类型筛选。
4. 分组创建、重命名、排序、删除，以及条目加入或移出分组。
5. 条目置顶、取消置顶、删除和再次复制。
6. 全局快捷键唤起、键盘导航、菜单栏入口。
7. 暂停记录、来源应用排除、敏感内容跳过及历史清理。
8. 浅色 / 深色模式、基础辅助功能支持和本地设置。

### 3.2 一期可选增强

- 图片与文件的系统快速预览（Quick Look）。
- 去格式复制、快捷操作、批量整理。
- 本地原生格式导出 / 导入与手动备份。
- 在用户明确授权后，将选中内容自动粘贴到原应用。

可选能力不得阻塞“记录 → 检索 → 复制”的基础闭环。

### 3.3 一期明确不做

- 跨设备自动同步、账号体系、服务器端管理与多人共享。
- iOS / iPadOS 客户端和 Android / Windows 客户端。
- 图片 OCR、语义搜索、AI 内容处理与插件系统。
- 任意应用全部私有剪贴板格式的无损恢复。
- 在无权限或后台受限的移动平台实现与 Mac 等价的持续剪贴板监听。

## 4. 主要使用场景

| 场景 | 期望行为 |
| --- | --- |
| 找回刚才复制的内容 | 快捷键唤起，最近记录优先展示，选择后再次复制 |
| 整理常用片段 | 加入工作、开发、生活等分组，并将高频条目置顶 |
| 复制截图或图片 | 展示缩略图、尺寸和大小，按需加载原图 |
| 复制一个或多个文件 | 展示名称、数量、类型和可用状态，再次复制有效文件引用 |
| 搜索旧记录 | 根据文本、链接或文件名检索，可叠加分组与类型筛选 |
| 临时复制敏感信息 | 暂停记录，或由来源排除和敏感标记规则跳过 |
| 长期后台使用 | 低开销运行，按策略清理，不无限增长磁盘占用 |

## 5. 功能设计

### 5.1 剪贴板采集

- 读取系统通用剪贴板 `NSPasteboard.general`，通过 `changeCount` 检测变化。
- macOS 不提供通用剪贴板变更通知；采用可调轮询间隔，初始建议 500 ms，并验证空闲与休眠恢复策略。
- 检测到变化后尽快读取所需数据，避免下一次复制覆盖内容；识别、哈希、索引和缩略图生成在后台执行。
- 一次剪贴板变化形成一个逻辑条目，允许包含多个 pasteboard item，以及同一 item 的多种内容表示。
- 保存支持格式的可用表示，不将剪贴板声明的所有类型都无条件读取或落盘。
- 对延迟提供的数据、文件承诺（file promise）、超大内容和应用私有格式进行能力检测，无法获取时提示或跳过，不影响后续采集。
- 采集采取单一串行写入顺序；处理过慢时使用有界队列与受控降级，记录遗漏计数，不能承诺捕获所有瞬时变化。
- 内容来源应用按复制发生时的前台应用进行尽力推断；来源信息可能不准确，排除规则不构成绝对安全边界。
- 监测到本应用执行再次复制时，使用进程内写入标记与 `changeCount` 对应关系抑制自采集，避免重复入库。

### 5.2 支持类型与兼容边界

| 类型 | 一期保存与预览方式 | 再次使用与限制 |
| --- | --- | --- |
| 纯文本 | 保存文本、摘要及搜索内容 | 写回纯文本表示 |
| 链接 | 保存原始文本与 URL 表示，展示域名 | 不自动联网抓取网页或预览，避免隐私泄露 |
| 富文本 | 保留可用的 RTF / HTML 表示，并提取纯文本 | 优先恢复已保存表示，不执行 HTML 脚本，不加载远程资源 |
| 图片 | 保存支持的原始表示，生成缩略图 | 按目标应用支持情况提供图片表示，不承诺所有应用私有信息保真 |
| 单个 / 多个文件 | 保存文件引用、元数据及可用的访问凭证 | 文件移动、删除或权限失效后可能不可用，需明确提示 |
| 不支持类型 | 仅提供受控的类型提示，默认不保存无意义条目 | 后续按真实使用场景扩展 |

**文件语义**：一期默认保存引用，不复制文件本体，因此“历史记录存在”不等于“原文件已备份”。在沙盒环境下，普通路径不足以保证重启后仍可访问；需验证剪贴板授权范围、security-scoped bookmark 的获取与恢复能力，不可获取持久访问权限时应提示用户重新授权。文件快照保留作为后续独立能力评估。

### 5.3 去重与保留

- 根据条目结构、类型和内容摘要生成稳定指纹；文件引用条目结合有序文件集合生成指纹，不默认读取整个文件内容计算哈希。
- 同一内容再次复制时更新最近复制时间和使用次数，保留已有分组与置顶状态。
- 富文本与纯文本即使显示文字相同，也不自动视为同一内容；图片原始表示不同也不承诺视觉去重。
- 默认建议保留最近 30 天、最多 10,000 条非保护记录，并设置总容量上限；任一阈值触发均执行清理。
- 默认置顶或已分组条目不参与自动清理，但仍计入容量统计；保护内容占满上限时提示用户，暂停保存新内容，不静默删除保护条目。
- 超限单条内容不落盘并提示原因；具体默认上限待技术验证确定。
- 删除条目时同步删除关联、搜索索引和未被引用的内容文件。

### 5.4 分组与置顶

- 分组一期采用单层结构，支持名称、颜色、图标与手动排序。
- 条目与分组为多对多关系，同一条目可归属多个分组。
- 删除分组默认仅解除关联，不删除条目；未加入分组的条目仍可从“全部”查看，不单设“未分组”入口。
- 置顶是条目全局属性；在当前筛选结果内置顶优先，同层按最近复制时间倒序。
- 一期不提供自定义置顶顺序和分组内独立排序，避免排序语义复杂化。

### 5.5 搜索与再次复制

- 非空关键词按类型做包含匹配：文本匹配正文（含可提取的富文本），链接匹配文本 / URL，文件仅匹配文件名；图片不参与关键词搜索（包括图片文件名）。不检索分组名、文件路径或文件正文；分组仍可作为独立筛选条件。搜索框为空时正常显示图片。
- 查询采取分页、短暂防抖与过期请求取消，避免每次输入扫描全部历史。
- 中文、英文、短词与子串检索需明确验证 SQLite 索引及分词策略；不能直接假设默认 FTS 分词满足中文需求。
- 单击条目仅更新选中态；回车或双击条目执行粘贴：写回系统剪贴板后收起面板并发送粘贴命令。
- 记录操作统一为“粘贴”：写入剪贴板后向打开列表时保存的目标应用发送 ⌘V，需辅助功能授权；当前实现优先捕获并恢复原窗口 / 输入节点，窗口变化、切换到其他输入框或快照失效时拒绝，快照不可用时退化为目标应用当前 responder；权限不足或目标不可用时提示并拒绝写入或发送，不自动提交。文本 / 链接另提供“粘贴为纯文本”，图片 / 文件隐藏此项。
- 自动粘贴须用户主动开启并授予辅助功能权限；确认目标应用前台后执行，权限不足或目标不可用时退化为仅复制。

## 6. UI 与交互方向

### 6.1 信息架构

- **菜单栏**：唯一常驻图标；点击或全局快捷键从图标下方展开同一个轻量浮层。
- **列表浮层**：紧凑搜索、横向分组、类型筛选、单列内容；复制、置顶和分组操作集中于此，点击外部或 Esc 收起。
- **按需详情**：条目内展开预览，不创建三栏管理窗口或独立详情窗口；低频操作收进更多菜单和右键菜单。
- **设置窗口**：通用、快捷键、记录与隐私、存储与清理；一期不展示不可用的同步开关。

### 6.2 视觉规范

- 使用系统字体、SF Symbols、系统语义色与适度材质效果，不依赖 WebView 构建主界面。
- 卡片重点展示内容摘要，弱化来源、时间、类型等辅助信息；置顶与分组标识清晰但不抢占主体。
- 图片以缩略图呈现，文件以类型图标和文件名呈现；长文本截断，详情中按需展开。
- 支持键盘上下移动、回车粘贴、Esc 关闭和清晰的焦点反馈；全局快捷键默认 `⇧⌘V`，允许修改并检查注册冲突。
- 尊重系统减少动态效果、降低透明度和辅助功能设置，保证 VoiceOver 标签与对比度。
- 覆盖空列表、搜索无结果、采集暂停、文件失效、权限不足、容量已满和数据库异常等状态。
- 界面默认不展示完整敏感内容；诊断与设置页不得意外泄露剪贴板正文。

## 7. 总体技术架构

```text
SwiftUI / AppKit 展示层
  ├─ 菜单栏与快捷面板
  ├─ 历史、分组、搜索与详情
  └─ 设置、隐私与状态提示
              │
应用用例层：采集编排、再次复制、分组、置顶、清理
              │
领域层：条目、表示、分组、去重、保留策略
              │
基础设施层
  ├─ NSPasteboard / 全局快捷键 / 应用焦点适配
  ├─ SQLite 元数据、搜索索引及迁移
  ├─ 内容文件、缩略图与文件访问凭证
  └─ 后续同步适配接口（一期不实现网络同步）
```

### 7.1 技术选型建议

| 模块 | 初始方案 | 选择原因与约束 |
| --- | --- | --- |
| 主界面 | SwiftUI | 原生开发效率与平台一致性 |
| 窗口与系统交互 | AppKit、NSPanel、NSStatusItem | 控制菜单栏、面板焦点和多显示器行为 |
| 剪贴板 | NSPasteboard + UniformTypeIdentifiers | 系统原生能力，按受支持类型读取 |
| 持久化 | SQLite，建议通过 GRDB 封装 | 便于关系建模、迁移、事务及全文索引；依赖版本与许可待核验 |
| 并发 | Swift Concurrency + actor | 隔离采集状态、数据库写入和后台任务 |
| 图片处理 | ImageIO / Quick Look | 生成降采样预览，避免完整解码超大图片 |
| 日志 | OSLog | 记录性能、状态和错误，不记录内容正文 |
| 分发 | Developer ID 签名与公证优先评估 | 是否采用 App Sandbox、是否上架 App Store 待技术验证后决定 |

数据库使用本机 SQLite，不依赖 Oracle。Oracle 默认环境约定仅适用于后续确有服务端数据库排查的场景，不应将桌面本地存储设计为远程数据库。

### 7.2 模块边界与执行规则

- `ClipboardMonitor`：监测变化、采集受支持表示、报告跳过或失败原因。
- `ClipboardService`：组织去重、写入、再次复制和保留策略。
- `HistoryRepository`：条目、分组、关系查询与事务；不承担 UI 状态管理。
- `AssetStore`：内容文件原子写入、按需读取、缩略图与孤立文件回收。
- `SearchService`：构建索引、执行分页查询和取消过期任务。
- `PrivacyPolicy`：统一处理暂停、排除、敏感标记和保存限制。
- `SystemIntegration`：全局快捷键、焦点切换、开机启动及权限适配。
- `SyncBoundary`：仅约定稳定标识、修订信息和删除传播需求，不提前建设同步队列或后台网络任务。

UI 更新在 `MainActor` 执行。剪贴板读取遵循 AppKit 的线程约束，实际解析、文件 I/O、数据库和图片处理不得在主线程执行；必要的主线程数据读取也须受大小与耗时限制。

## 8. 数据模型初稿

元数据采用关系表；二进制内容与大文本存放于应用专属目录，数据库只保存引用、摘要及必要的可检索文本。所有业务字段均禁止使用 JSON 存储多值或结构化数据。

| 实体 / 表 | 核心字段及含义 |
| --- | --- |
| `clipboard_entry` | `id`：稳定 UUID；`kind`：主展示类型；`fingerprint`：内容指纹；`created_at`：首次记录时间；`last_copied_at`：最近复制时间；`copy_count`：复制次数；`is_pinned`：是否置顶；`source_bundle_id`：推断来源；`revision`：本地修订版本 |
| `clipboard_item` | `id`、`entry_id`、`item_order`：表示一次复制中的各个独立 item，保留原始顺序 |
| `content_representation` | `id`、`item_id`、`uti`、`asset_id`、`byte_size`、`representation_order`：同一 item 的多种内容表示及其顺序 |
| `asset` | `id`、`relative_path`、`content_hash`、`byte_size`、`storage_kind`：内容或预览文件的存储信息 |
| `file_reference` | `id`、`item_id`、`file_order`、`original_path`、`display_name`、`bookmark_data`、`availability`：文件顺序、访问凭证及最近检查状态 |
| `user_group` | `id`、`name`、`color_token`、`icon_name`、`sort_order`、`created_at`、`updated_at`：用户分组 |
| `entry_group` | `entry_id`、`group_id`、`added_at`：条目与分组的多对多关联，组合唯一 |
| `search_document` | `entry_id`、`plain_text`、`url_text`、`file_names_text`：派生搜索文档，不作为内容恢复来源 |
| `excluded_application` | `bundle_id`、`display_name`、`created_at`：不记录的来源应用配置 |

建模约束：

- 条目、分组等未来需同步的对象采用稳定 UUID；不使用本机自增 ID 作为跨设备身份。
- 多值关系使用关联表；`bookmark_data` 是系统授权凭证二进制数据，不是业务 JSON。
- 索引覆盖最近复制时间、置顶、内容指纹、关联表及搜索查询；通过迁移文件维护 schema 版本。
- 文件先写临时路径并原子改名，再提交元数据事务；失败时清理临时文件，启动时修复孤立文件与缺失引用。
- 派生缩略图允许重建；原始内容与元数据不能因缩略图生成失败而丢失。
- 一期删除为本地删除；真正启用同步前引入 tombstone、变更日志和保留期限，避免无用途地永久积累删除数据。
- 单机偏好可使用 `UserDefaults` 的明确类型字段；不得将核心业务对象序列化成 JSON 塞入配置字段。

## 9. 性能与容量目标

基准暂定 Apple Silicon、16 GB 内存、10,000 条元数据记录，图片和文件内容按需加载；最终指标需在最低支持硬件和签名构建上实测。

| 指标 | 初始验收目标 |
| --- | --- |
| 快速面板热唤起 | P95 ≤ 150 ms，以可交互首屏出现为准 |
| 本地搜索 | P95 ≤ 100 ms，不含输入防抖等待和首次索引构建 |
| 普通文本入库 | 检测到变化后 P95 ≤ 200 ms，不含轮询等待 |
| 空闲 CPU | 观察窗口内平均占单核 ≤ 1%，需包含轮询成本 |
| 空闲常驻内存 | 目标 ≤ 150 MB；大型内容处理峰值另行限额 |
| 列表渲染 | 日常滚动目标 60 fps，避免同步解码和主线程全量查询 |
| 默认存储上限 | 初选 1 GB，可配置；含原始内容、索引、缩略图与临时空间预算 |

关键措施：分页与懒加载、缩略图降采样、有界缓存、后台索引、批量清理及可取消任务。SQLite WAL 模式需结合实际并发方式验证，并处理 checkpoint 与空间回收，不能只限制内容文件大小。

## 10. 隐私、安全与权限

- 一期不上传剪贴板内容，不引入广告或内容分析 SDK，不因链接预览自动访问网络。
- 首次启动解释记录范围、存储位置、文件引用语义及暂停 / 删除方式，由用户明确开启记录。
- 识别支持的密码管理器或应用敏感标记并跳过；兼容性逐项验证，不能宣称能识别所有密码。
- 不依赖正则表达式判定“内容绝对安全”，也不对所有未标记内容作安全承诺。
- 提供排除来源应用、暂停记录、按时间清理与清空历史，以及包含置顶和分组内容的彻底清理入口。
- 应用数据目录采用当前用户最小访问权限，密钥若有需要存入 Keychain；一期不宣称应用级静态加密，系统 FileVault 也不等价于应用自身加密。
- 日志仅包含匿名条目标识、类型、大小、耗时和错误码；不得记录正文、完整路径、访问凭证或密钥。
- 数据删除采用逻辑与文件清理，不承诺在 SSD、SQLite 页面、系统快照或备份中实现安全擦除。
- 逐项验证目标 macOS 的剪贴板隐私行为与提示；基础记录和复制不应以辅助功能授权为前提。
- 不请求屏幕录制或完全磁盘访问权限作为普通采集的默认前置条件。

## 11. 跨设备同步与移动端演进

### 11.1 同步预留

一期仅提供可扩展的数据标识和模块边界，不实现账号、云端读写、实时通道或设备发现。

后续建议优先评估 CloudKit 私有数据库，结合 Apple 生态的账号体验、成本、容量、加密要求及数据区域再决定，不能在本阶段承诺具体服务。

后续同步设计必须另行明确：

- 用户选择开启、设备准入、同步范围和敏感内容排除。
- 元数据与大体积资产分离传输，支持幂等、重试、断点恢复和离线补偿。
- 内容去重、分组多对多关系冲突、置顶更新与删除冲突的确定性规则。
- 墓碑传播、离线设备保留期、时间漂移与版本迁移。
- 文件引用不具有跨设备可移植性；同步文件必须引入明确的内容上传与接收语义。
- 云端加密、端到端加密及密钥恢复需要单独评审，不默认认为私有云数据库等于端到端加密。

### 11.2 手机端扩展

- 共享领域规则、稳定标识、存储协议与同步协议，UI 和平台能力独立适配。
- iOS / iPadOS 存在剪贴板访问提示及后台执行限制，不承诺手机端持续后台自动采集。
- 手机端优先考虑前台读取、分享扩展主动保存和已同步内容浏览 / 复制。
- 系统 Universal Clipboard 不能替代持久历史同步，二者边界与重复采集策略需单独验证。

## 12. 里程碑与验证方式

| 阶段 | 交付内容 | 验收重点 |
| --- | --- | --- |
| M0：技术验证 | 剪贴板多表示采集、面板焦点、文件引用恢复、权限与沙盒实验 | 明确能做什么、不能做什么，确定最低系统及发行渠道 |
| M1：最小闭环 | 菜单栏、快捷面板、文本 / 链接采集、本地持久化、搜索、再次复制 | 从复制到找回的完整体验 |
| M2：内容与管理 | 图片、文件、富文本、分组、置顶、去重、失效提示 | 多类型正确性与管理规则一致 |
| M3：体验与稳定性 | 性能优化、隐私、清理、异常恢复、视觉打磨 | 指标、低开销与长期运行稳定性 |
| M4：发布准备 | 签名公证、安装升级、迁移、用户说明 | 干净环境安装、升级数据不丢失与可排障 |

自动化验证使用独立的命令行隔离回归（`native/scripts/check-regressions.sh`）和真实跨进程 AX 回归（`native/scripts/check-ax.sh`），不使用 XCTest 测试类；系统交互、性能与兼容性仍通过人工验证和 Instruments 实测，不以静态检查或合成回归代替运行验证。

人工验收至少覆盖：

- 常用编辑器、浏览器、办公工具、Finder、截图工具之间的复制与恢复。
- 多文件、多表示、超大内容、不支持类型、文件移动和权限失效。
- 中文搜索、短词搜索、组合筛选、重复复制及置顶 / 分组保留。
- 暂停记录、来源排除、敏感标记、日志脱敏和全部清理。
- 休眠唤醒、重启恢复、多显示器、全屏空间及快捷键冲突。
- 数据库写入失败、磁盘空间不足、处理中退出及迁移失败恢复。

## 13. 主要风险与应对

| 风险 | 应对措施 |
| --- | --- |
| 高频复制在轮询间隙被覆盖 | 明确尽力采集语义，验证轮询成本，不承诺零丢失 |
| 剪贴板格式复杂且部分数据延迟提供 | 支持类型白名单、大小限制、兼容性清单与失败隔离 |
| 文件引用无法长期或跨设备访问 | 显示失效状态，验证授权恢复，文件快照另行设计 |
| 敏感信息漏识别 | 用户主动控制优先，不将自动识别当作可靠安全隔离 |
| 大图片导致卡顿或磁盘膨胀 | 大小限制、后台处理、降采样、容量预算与有界缓存 |
| App Sandbox 与分发渠道影响功能 | 在 M0 使用实际签名配置验证，不推迟到发布前 |
| 后续同步导致隐私或模型返工 | 稳定身份、表示分层、显式文件语义与独立同步评审 |

## 14. 待确认事项

1. “只支持 Apple 系列”是否明确指 Apple Silicon Mac，是否接受最低 macOS 14？
2. 正式产品名称、图标与视觉偏好：偏系统原生克制风格，还是更强的品牌表达？
3. 首发渠道是官网分发、Mac App Store，还是两者兼顾？
4. 文件管理一期是否接受“仅保存引用”，还是必须保存文件快照？
5. 默认保留 30 天 / 10,000 条 / 1 GB 是否合适，分组条目是否默认长期保护？
6. 自动粘贴是否列为一期必做，还是仅提供再次复制？
7. 是否要求应用级本地加密，以及应用锁定 / 预览遮挡能力？
8. 后续同步是否只覆盖个人 Apple 设备，是否存在非 Apple 平台或共享需求？
